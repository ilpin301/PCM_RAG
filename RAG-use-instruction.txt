================================================================
PCM_RAG — HOW TO USE (quick instruction)
================================================================

Your knowledge base: LightRAG GraphRAG server, web UI + REST API at
http://localhost:9622, API key: (stored in lightrag/.env as LIGHTRAG_API_KEY — never hardcode)

----------------------------------------------------------------
1. WHAT MUST BE RUNNING
----------------------------------------------------------------

BEFORE ASKING QUESTIONS:
  1. Docker Desktop (check: docker info)
  2. LightRAG container:
       cd X:\RAG_MAIN\PCM_RAG\lightrag
       docker compose up -d
     check: open http://localhost:9622 in browser, or:
       $key = (Get-Content X:\RAG_MAIN\PCM_RAG\lightrag\.env | Select-String '^LIGHTRAG_API_KEY=').Line.Split('=',2)[1].Trim()
       curl.exe -s http://localhost:9622/health -H "X-API-Key: $key"
  3. Ollama (embeddings for query context lookup):
       check: curl.exe -s http://localhost:11434/api/version

BEFORE INGESTING FILES (additionally):
  4. STOP the container first (ingest writes the same storage files):
       docker compose stop
     ...then start it again after ingest:
       docker compose start
  5. ZAI_API_KEY environment variable must be set.

----------------------------------------------------------------
2. HOW TO ASK A QUESTION
----------------------------------------------------------------

WAY A — Web UI (easiest):
  Open http://localhost:9622, login with the API key.
  Query tab: type question, pick mode (hybrid = default best).
  Graph tab: explore entities/relationships visually.

WAY B — Claude Code (this project):
  Open Claude Code in X:\RAG_MAIN\PCM_RAG and just say:
    "ask the rag: what does the biomass ash paper say about porosity?"
  Claude uses the lightrag-query skill automatically.

WAY C — Direct API (PowerShell, works from any script):
  $key = (Get-Content X:\RAG_MAIN\PCM_RAG\lightrag\.env | Select-String '^LIGHTRAG_API_KEY=').Line.Split('=',2)[1].Trim()
  $h = @{'X-API-Key'=$key; 'Content-Type'='application/json'}
  $body = '{"query":"YOUR QUESTION","mode":"hybrid"}'
  (Invoke-RestMethod http://localhost:9622/query -Method Post -Headers $h -Body $body).response

  Query modes:
    hybrid - default, best for most questions
    local  - details about one specific thing
    global - big picture, comparisons, themes
    naive  - plain text search, quote finding
    mix    - graph + vector combined

----------------------------------------------------------------
3. HOW TO INGEST NEW DOCUMENTS
----------------------------------------------------------------

RULE: put files ONLY into X:\RAG_MAIN\PCM_RAG\IN\ first.
Never ingest from other folders.

Simple text PDFs: upload via Web UI (drag & drop) — server must be UP.

Scanned / chart-heavy PDFs (full pipeline: MinerU + GLM vision):
  In Claude Code say: "ingest the new PDFs in IN folder into the rag"
  (il-rag-ingest skill does everything: routing, slicing, launching the
   ragkit launcher detached, waiting, verifying, bookkeeping).

  Manual alternative — this base has NO launcher of its own any more;
  everything runs through the shared kit at %RAGKIT_HOME%:
    1. write the PDF paths, one per line, UTF-8, into
       X:\RAG_MAIN\PCM_RAG\lightrag\ingest_list.txt
    2. Start-Process pwsh -ArgumentList "-NoProfile","-File","$env:RAGKIT_HOME\ingest.ps1",
         "-Root","X:\RAG_MAIN\PCM_RAG","-ListFile","X:\RAG_MAIN\PCM_RAG\lightrag\ingest_list.txt" -WindowStyle Hidden
       (the launcher stops docker itself — do NOT stop it first)
    3. watch: Get-Content X:\RAG_MAIN\PCM_RAG\lightrag\LOG\ingest_run.log -Wait -Tail 20
    4. success = EXITCODE=0, the log is deleted, Ring10.wav plays and docker
       restarts automatically. Failure = the log is kept as
       ingest_FAILED_<stamp>.log, LAST_FAILURE.txt holds the triage verdict,
       and Windows Critical Stop.wav plays.

  Verify after: ask "did ingestion finish?" in Claude Code
  (lightrag-status skill) — documents must show PROCESSED.

----------------------------------------------------------------
4. USING THE RAG WITH OTHER AI MODELS (GLM-5.2 etc.)
----------------------------------------------------------------

The answers are ALREADY generated by GLM-5.2: every /query call
retrieves graph context and lets glm-5.3 (via z.ai) write the answer.
You don't need to connect another model for normal use.

Any external tool/model/agent CAN use the RAG — it is a plain HTTP API:
  POST http://localhost:9622/query
  headers: X-API-Key: (stored in lightrag/.env as LIGHTRAG_API_KEY — never hardcode)
           Content-Type: application/json
  body:    {"query":"...","mode":"hybrid"}

So any client that can make HTTP calls works:
  - GLM-5.2 / Claude / any agent with a "call API" or MCP-http tool
  - python: requests.post(...) with the headers above
  - curl / PowerShell scripts
  - to feed RAG answers INTO another model: call /query first, then
    paste the "response" text into that model's prompt as context.

Full interactive API reference: http://localhost:9622/docs

----------------------------------------------------------------
5. RULES THAT KEEP IT ALIVE
----------------------------------------------------------------

  - Ollama must be UP before any ingest (silent embedding failures otherwise).
  - Container must be STOPPED during rag_ingest.py runs. The kit launcher
    does this for you; never run the python directly.
  - Never change the embedding model (bge-m3) — old vectors become garbage.
  - Ingest interrupted? Safe. Re-run — caches make it cheap. But queries
    only work after a run finishes cleanly (EXITCODE=0).
  - More details: X:\RAG_MAIN\PCM_RAG\USAGE.md
